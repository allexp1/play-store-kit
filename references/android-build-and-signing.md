# Building and signing for Play

How `scripts/build.py` finds, builds, inspects and binds an Android App Bundle, and the signing model Play expects.
Limits quoted here live in `scripts/rules.json`; the rules page is `precheck-rules.md`.

## The artifact record

Every adapter ends in the same record, which the plan binds by SHA-256 before any upload:

`path, sha256, package, version_code, version_name, min_sdk, target_sdk, signer_sha256, abis, native_libs[],
dex_total_bytes, compressed_download_bytes, mapping_path, native_symbols_path`

`python3 scripts/build.py inspect --aab app-release.aab --json` prints it. The record is always read from the built
AAB (`bundletool dump manifest`), never from `src/main/AndroidManifest.xml`: the merged manifest is what Play sees.

## Adapters (`project.yaml → kind`)

| Kind | Build | Output | Version source (`bump`) |
|---|---|---|---|
| `gradle` | `./gradlew :<module>:bundle<Variant>` | newest `*.aab` under `<module>/build/outputs/bundle/<variant>/` | an integer literal `versionCode = N` / `versionCode N` in that module's build file; anything computed → instructions |
| `flutter` | `flutter build appbundle --release` | `build/app/outputs/bundle/release/` | `pubspec.yaml version: x.y.z+N` (unless `android/app/build.gradle` overrides it) |
| `react-native` | Gradle in `android/` | as Gradle | Gradle literal |
| `expo` | `npx expo prebuild` then Gradle in `android/`; EAS cloud builds → `external` | as Gradle | `app.json → expo.android.versionCode` |
| `unity` | export a Gradle project, or build the AAB in Unity → `external` | — | Player Settings → instructions only |
| `external` | none | the path you give | none |

`build_command` in `project.yaml` overrides the default; it runs without a shell (split like a command line), in
the project root. Output selection is restricted to the selected module and picks the newest file, then the hash is
recorded — the kit never uploads "the first match of a glob". `output_glob` may be absolute (or start with `~`).
If build.gradle moves the build directory (`layout.buildDirectory`, `buildDir`), the default glob finds nothing:
`bundle` then asks Gradle for the module's `buildDir` and looks there, or tells you to set `output_glob`.

Gradle needs JDK 17+. `bundle` uses `project.yaml → java_home`, else `JAVA_HOME` (or `java` on PATH when it is
unset), else `/usr/libexec/java_home -v 17+`, else Android Studio's JBR, skips anything below 17, and reports the
one it used under `jdk`.

Gradle is executable configuration. `bump` edits only a plain integer it can see; a version derived from a property,
a CI variable or a plugin gets a printed instruction instead of a regex edit.

Release checklist for any framework:
- release build type, `debuggable` false, minify/R8 on (mapping file produced);
- React Native: `index.android.bundle` inside the AAB (a debug build fetches JS from Metro);
- Unity: IL2CPP with ARM64 ticked;
- Flutter: `--obfuscate --split-debug-info=<dir>` if you want symbolicated Dart stacks (upload the symbols yourself).

## Play App Signing

Since August 2021 new apps must publish as AABs with Play App Signing. There are two keys:

| Key | Who holds it | Used for |
|---|---|---|
| **App signing key** | Google | signs the APKs that users install; generated by Google (recommended) or uploaded once at enrolment |
| **Upload key** | you | signs the AAB you upload; Play verifies it and discards the signature |

- The kit compares the AAB signer's SHA-256 with `console.yaml → upload_certificate_sha256`, copied from
  Play Console → *Test and release → App integrity → Play app signing* (upload key certificate).
- A lost or leaked upload key can be reset from App integrity ("Request upload key reset"); it needs the account
  owner, a new certificate (PEM) and a waiting period before the new key works. The app signing key cannot be reset
  this way — protect the upload keystore and its passwords outside the repo.
- Keep the keystore and `keystore.properties` out of git (`validate_kit.py` fails if `*.jks`, `*.keystore` or
  `keystore.properties` are tracked). Point Gradle at them through `~/.gradle/gradle.properties` or environment
  variables.
- The first AAB of a new app is uploaded by the person in the Console; the API cannot create apps.

Generate an upload key (once):

```bash
keytool -genkeypair -v -keystore ~/keys/upload.jks -alias upload \
  -keyalg RSA -keysize 4096 -validity 10000
keytool -list -v -keystore ~/keys/upload.jks -alias upload   # SHA-256 fingerprint
```

Source: https://support.google.com/googleplay/android-developer/answer/9842756 ,
https://developer.android.com/studio/publish/app-signing

## bundletool commands the kit runs

`bundletool` (jar via `BUNDLETOOL_JAR`, or on `PATH`) and a JDK 17+ are needed for inspection.

```bash
bundletool validate --bundle app.aab
bundletool dump manifest --bundle app.aab              # package, versionCode, targetSdk, permissions, meta-data
bundletool dump config --bundle app.aab                # PAGE_ALIGNMENT_16K = packaging intent only
bundletool build-apks --bundle app.aab --output /tmp/app.apks   # unsigned is fine for sizing
bundletool get-size total --apks /tmp/app.apks         # compressed download size (MIN,MAX)
```

`build.py size` runs the last two. The raw AAB size is not the download size and is never compared with limits.

## Native code: 64-bit and 16 KB pages

- Every ABI with 32-bit code needs its 64-bit twin (`armeabi-v7a` → `arm64-v8a`, `x86` → `x86_64`).
- 16 KB page sizes: every 64-bit `.so` must have `PT_LOAD` segments aligned to at least 16384.
  `python3 scripts/build.py elf-check --aab app.aab` reads the ELF program headers directly (no NDK needed).
  32-bit libraries are listed as "n/a" because 16 KB devices are 64-bit.
- Fixes: AGP 8.5.1+ with uncompressed native libs (the default) aligns the zip; NDK r28+ compiles 16 KB-aligned by
  default (r27: `-Wl,-z,max-page-size=16384`); prebuilt SDK libraries need a newer SDK version — the check names the
  library and its path.
- Run the app once on a 16 KB emulator image (Android 15+ "16 KB Page Size" system image); record it as attested.

Source: https://developer.android.com/guide/practices/page-sizes

## versionCode

- A positive integer, at most 2,100,000,000; each upload needs a code higher than any code Play has seen for the
  package on any track — a code is burned once uploaded, even if the release is discarded.
- `versionName` is free text shown to users; Play does not compare it.
- `release.py plan` checks the code against the latest `import` snapshot and `releases/release-history.yaml`.

Source: https://developer.android.com/studio/publish/versioning

## Mapping and native symbols

- R8/ProGuard: `<module>/build/outputs/mapping/<variant>/mapping.txt` → uploaded as `proguard` for that exact
  versionCode in the same edit, so Play Console and vitals deobfuscate stack traces.
- Native debug symbols: set `android.buildTypes.release.ndk.debugSymbolLevel = 'SYMBOL_TABLE'` (or `FULL`) and AGP
  puts them in the AAB; a separate `native-debug-symbols.zip` is uploaded as `nativeCode`.
- Paths come from `project.yaml → mapping_path / native_symbols_path`; a missing mapping with minify on is a
  WARNING (and W-DEX from 2027-02-01).
